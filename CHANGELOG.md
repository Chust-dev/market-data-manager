# Changelog

## Unreleased

### Session B — Manage pillar build-out

- Fixed non-symbol directories leaking into `cache audit` output (BACKLOG #52): the pool walker now skips any subdirectory that doesn't contain at least one 4-digit-year child. Previously `Exports/` (nested inside the user's `D:\MarketData` pool by default), `.git`-style metadata folders, and stray temp dirs all showed up as bogus symbols with zero coverage in audit / `--by-year` / `--by-month` output. Fix is purely structural — no dependency on `instruments.json.digits`, so symbols the user is tracking but hasn't curated yet still register. The sibling Manage-pillar classes (`CacheVerifier`, `CacheCleaner`, `CacheRepairer`) were already immune (they only emit per-file results), so no change needed there. 4 new tests cover Exports-style neighbours, junk neighbours with no year structure, empty year subdirs (still a valid symbol), and 2-digit-year-like subdirs that shouldn't match.


### Session B — Manage pillar build-out

- Extended `cache audit` with per-year and per-month coverage grids (BACKLOG #14): `--by-year` adds a row-per-symbol × column-per-year grid showing yearly coverage; `--by-month` adds a per-symbol year × Jan–Dec grid for drilling into specific gaps. Smart default: when the audit is scoped to a single symbol (via `--instrument SYM` or `--symbols SYM`), the month grid is auto-included since the output is bounded; pass `--no-by-month` to suppress. Coverage = `cached_hour_files / (weekdays_in_month × 24)`; cells show percentage or `-` for zero-file months (typically start/end of a symbol's history). Computation piggybacks on the existing pool walk via a new `HourTickFilesByMonth` dictionary on `SymbolAuditReport` — no additional I/O. New public static helpers `PoolAuditor.ExpectedWeekdayHoursInMonth` / `ExpectedWeekdayHoursInYear`. 8 new tests cover per-month bucketing, both renderers, empty-pool fallback, and exact weekday counting for January 2025 (23 weekdays) and February 2025 (20 weekdays).

- Added `--start ISO` / `--end ISO` range filter to `cache verify`: scopes the run to files whose (year, calendar-month, day) falls within the given bounds (inclusive, either may be omitted). Implemented at the planner level via `CacheVerifier.PlanFiles(symbolFilter, fromUtc, toUtc)`, which short-circuits whole year/month/day folders that fall outside the range. Applies to both local and remote checks; the main lever for keeping a full-pool drift check tractable ("probe just last quarter"). 5 new tests cover both bounds independently, both together, empty intersection, and null-bounds passthrough.
- Bumped `cache verify --remote` default parallelism from 4 to 8: empirically still well within Dukascopy's tolerated concurrency, and roughly halves wall-clock time for drift checks. Raise via `--parallel N` if your network can sustain more; dial back if you start seeing `RemoteUnreachable` clusters.
- Added per-symbol parallel probing to `cache verify --remote`: `--parallel N` fans out source-side probes across N concurrent tasks. Sequential probing was impractical on full-pool drift checks — a 50k-file symbol took hours per run at parallel=1. Local Inspect remains sequential (CPU-bound, not the bottleneck); only the network probe step is parallelised, with a single report lock guarding the per-symbol counts and mismatch lists. Report renders `parallel=N` alongside the existing `byte-exact` / `size-only` mode label. 2 new tests cover correctness under parallelism=8 (50 files across 2 symbols, mixed drift outcomes) and that the default falls through to `CacheVerifier.DefaultRemoteParallelism`.

- Extended `cache verify` with source-side drift detection (BACKLOG #13): `--remote` adds a per-file probe to Dukascopy for each locally-clean file, comparing local size and (by default) hash against the source. **Default is byte-exact** — streams the body through SHA-256 on the fly and compares; catches all drift including content changes that preserve length. Pass `--size-only` to fall back to a Content-Length compare without body download (faster but won't detect same-size content changes). Files that fail the local check are NOT probed remotely (no point burning network on known-bad files). Remote outcomes (`RemoteOk` / `RemoteSizeMismatch` / `RemoteHashMismatch` / `RemoteUnreachable`) are reported alongside local outcomes; `AllClean` now requires both. New `IRemoteFileProbe` interface decouples the verifier from `DukascopyClient`; production wrapper is `DukascopyRemoteFileProbe` and the new public `DukascopyClient.ProbeFileAsync` exposes the underlying network primitive. 12 new tests cover all five remote outcomes, byte-exact vs size-only modes, locally-bad file skipping, mixed outcomes, cancellation, and report rendering.

- Added `cache cleanup` subcommand (BACKLOG #21): destructive removal of files that are definitively useless — zero-byte `.bi5` downloads, orphan `.meta.json` sidecars (no matching data file), and leftover `.tmp` files from interrupted writes. After deletion, prunes empty day/month/year directories so the tree stays tidy; preserves the symbol root even if empty. **Deletes by default**; pass `--dry-run` to preview without changes (per the user-chosen safety default — opposite of `cache repair`'s preview-by-default). Honours `--instrument` / `--symbols` filters and `--quiet`. Wired into the cross-pillar `ProgressBar`. Deliberately does NOT remove hash-mismatched files (that's `cache repair`'s job) or symbols missing from `instruments.json`. 16 new tests cover dry-run, each removal category, accompanying-sidecar deletion, symbol filter, empty-dir pruning, symbol-root preservation, cancellation, and report rendering.

- Added `cache repair` subcommand (BACKLOG #20): closes the verify→fix loop. For each problem file flagged by the same per-file logic that drives `cache verify`, dispatches one of two actions: **Refetch** (re-download from Dukascopy via a new public `DukascopyClient.RefetchFileAsync` primitive) or **RegenerateSidecar** (trust the local file, write a fresh `.meta.json` from current bytes). Default action for `SizeMismatch` / `HashMismatch` / `NoMetadata` is Refetch; `--trust-existing` flips the NoMetadata default to RegenerateSidecar so users with old pre-sidecar caches don't pay full re-download cost. `--dry-run` reports the planned actions without touching the cache. Honours `--instrument` / `--symbols` filters and `--quiet`. ProgressBar wired against the same FilesProcessed counter pattern as verify. Orchestration is decoupled from network via a new `IFileRefetcher` interface, allowing the Manage-pillar `CacheRepairer` to be unit-tested with a fake refetcher (16 new tests). Exit code 0 if clean or fully repaired, 1 if anything is still bad — suitable for scheduled drift detection.
- Renamed Manage pillar folder/namespace from `Audit/` to `Manage/` to match the project's canonical pillar naming. Class names tied to the `cache audit` subcommand (`PoolAuditor`, `CacheAuditCommand`, etc.) keep their `Audit` prefix because they relate to the verb, not the pillar. README architecture diagram and body text updated.

- Added `cache verify` subcommand (BACKLOG #12): recomputes SHA-256 on every cached `.bi5` file and compares against the `<file>.bi5.meta.json` sidecar written at download time. Reports per-symbol and aggregate counts of Ok / NoMetadata / SizeMismatch / HashMismatch / IoError outcomes, plus a capped detail list of the first 100 problematic files. Pure offline — no Dukascopy traffic. Honours `--instrument` / `--symbols` filters and `--quiet`. Wired into the cross-pillar `ProgressBar` (two-phase API: `PlanFiles` enumerates upfront so the bar knows the total, `RunPlan` does the SHA-256 work while polling the verifier's `FilesProcessed` counter). Exit code 0 if every cached file verifies clean, 1 otherwise — suitable for scheduled drift detection. `Ctrl+C` cancels mid-run.

### Known issues (parked from Session A)

- `cache discover` conflates clean "not available" responses with transient HTTP errors and writes both as `null` in `instruments.json`. The idempotent skip filter then permanently treats the symbol as unavailable until `--refresh` is passed. Workaround: re-run with `--refresh`. Fix planned post-Session-A.
- A duplicate progress bar line can appear on Ctrl+C when cancelling mid-run. Cosmetic only; the underlying cancellation path is correct.

### Session A — weekly workflow ready

- Added `cache discover` subcommand: binary-searches Dukascopy to find the earliest available date per symbol and records it in `instruments.json`. Supports single-symbol, explicit list, and `--symbols all` modes; results merge into the existing config without disturbing the `digits` map. Idempotent (already-discovered symbols are skipped on re-run); pass `--refresh` to re-probe. Configurable via `--since YYYY-MM-DD` (default 2000-01-01) and `--parallel N` (default 4).
- Added `cache catchup` subcommand: refreshes the rolling N-day window of the `.bi5` cache. Forces `RefreshCache=true` and `RecentRefreshDays = window + 1` so the entire window is re-fetched from Dukascopy each run, capturing Dukascopy's amendments to recent ticks. Defaults to 60 days; override with `--window N`. Designed for scheduled / weekly maintenance: `cache catchup --symbols all --no-prompt` is cron-friendly.
- Extended `instruments.json` schema with `earliest` and `latest` sections (additive, backward-compatible — existing digits-only files load unchanged). The `Save` method writes atomically (`.tmp` + rename) so a crash mid-write can't corrupt the file.
- Added cross-pillar `ProgressBar` utility (`src/ConsoleApp/Utils/ProgressBar.cs`): in-place updating bar with percent, current/total counts, and computed ETA. Generic over a `Func<long>` counter source so any pillar can plug in its own current-value supplier. Falls back to milestone lines when output is redirected (non-TTY); silenced entirely with `--quiet`. Wired into the Download pillar's main download loop, gap repair, and M1 validation passes.
- `--verbose` flipped to opt-in (default OFF). Previous behaviour printed every "Downloading ..." URL by default and interleaved with the progress bar; opt-in keeps the bar clean for normal use. Pass `--verbose` to restore the old per-URL trace output for debugging.
- Added `--quiet` flag: silences progress bars, banners, URL traces, and per-instrument summaries. Useful for scheduled tasks that just need the exit code. Independent from `--verbose`; `--quiet` wins if both are passed.
- Crash-recovery hardening: any `.tmp` files older than 1 hour are cleaned up at the start of each `cache update` run. Scoped to ONLY the symbols in the current request — concurrent runs on different symbol sets stay safe. These are leftovers from previous interrupted downloads that are never recovered or used.
- HTTP timeout vs cancellation: `TaskCanceledException` from `HttpClient` (request timeout) is now distinguished from real user cancellation (Ctrl+C) using exception filters (`when (cancellationToken.IsCancellationRequested)`). Timeouts are treated as transient failures the retry loop handles; only Ctrl+C aborts the run. Batch summary now reports a separate `Cancelled` count, replacing the misleading "Failed: 0, Succeeded: 0" output that used to appear on Ctrl+C mid-run.

### Refactor (pre-Session A)

- **Refactor (Layer 3)**: Internals reorganized around three pillars matching the cache-centric architecture. The Download pillar (`src/ConsoleApp/Download/Downloader.cs`) is now the only place network calls originate — it fills the `.bi5` cache. The Display pillar (`PoolAuditor`, unchanged) reads the cache without modification. The Export pillar (`src/ConsoleApp/Export/BarExporter.cs`, `TickExporter.cs`) reads the cache and projects it into MT5-compatible files. Each subcommand class now calls exactly one pillar directly, taking its typed options record without translating through `AppOptions`. The legacy flat-flag CLI continues to use the pre-refactor unified engine.
- **Refactor (Layer 2)**: Each subcommand now has its own typed options record (`CacheAuditOptions`, `CacheUpdateOptions`, `BarExportOptions`, `TickExportOptions`) parsed via shared `CommonParsingHelpers`. The four commands no longer share one "god record" of every possible option. Legacy `AppOptions` remains as a transitional bridge to the engine; Layer 3 will replace it with command-specific entry points.
- **Refactor (Layer 1)**: Introduced subcommand CLI surface — `cache update`, `cache audit`, `export bars`, `export ticks`. Each subcommand is a dedicated class implementing `ICommand`. The legacy flat-flag invocation (`--instrument X --start Y ...`) continues to work as a compatibility shim. Internal pipeline extracted into `Program.RunDownloadFlow` for reuse.
- Added `OutputFormat.None` so `cache update` can run the engine without producing any bar export files.
- Added `--audit` flag: prints a fast (no-decompression) summary of cached `.bi5` files in the pool — per-symbol date range, file counts, coverage rate, disk usage, and empty-file detection.
- Added `--export-ticks` flag: writes per-month tick CSVs alongside the M1 CSV/HST output, in MT5 Symbol Editor import format. Requires `--mode ticks`.
- Expanded `instruments.json` to 29 symbols (G10 majors, crosses, and XAUUSD).
- `--pool` and `--output` defaults changed to `D:\MarketData` and `D:\MarketData\Exports` for the local development setup.
